# Оценка поиска Kube Triage

## Протокол

- Корпус состоит из 134 фрагментов десяти русскоязычных страниц Kubernetes, привязанных к коммиту из `data/sources.json`. Эталон — раздел с ответом. Вопросы вне корпуса не учитываются в Hit@5 и MRR@5.
- Новая разметка содержит 48 вопросов. В каждом наборе по 16 вопросов с ответом и по 8 без ответа. Группы намерений `dev` и `test` не пересекаются. Эталонные разделы проверены по корпусу. Наборы первой версии сохранены отдельно.
- Скрипт проверяет первые пять фрагментов, возвращённых HTTP API, без удаления повторов при подсчёте. Hit@5 означает наличие эталонного раздела среди них. MRR@5 учитывает позицию первого попадания.
- p50 и p95 измерены после прогрева по всем 24 HTTP-запросам каждого режима, включая сериализацию и клиентскую задержку. Запросы выполнялись последовательно на CPU Windows с Qdrant в WSL 2.
- Вариант и порог выбирались на `dev`. При равных Hit@5 и MRR@5 преимущество получал вариант с меньшим числом повторов. На `test` параметры остались зафиксированными.

## Сравнение на test

| Вариант | Hit@5 | MRR@5 | Запросы с повторами разделов | p50 / p95 |
| --- | ---: | ---: | ---: | ---: |
| BM25 со стеммингом | 16/16 | 0,9375 | 7/24 | 5,1 / 6,7 мс |
| E5 + Qdrant | 16/16 | 0,8646 | 9/24 | 60,8 / 73,4 мс |
| RRF по фрагментам | 16/16 | 0,9375 | 9/24 | 58,5 / 84,1 мс |
| **RRF по разделам** | **16/16** | **0,9688** | **0/24** | **57,0 / 75,8 мс** |
| RRF по разделам с переранжированием | 16/16 | 0,9271 | 0/24 | 53,9 / 79,9 мс |

Вариант по разделам учитывает раздел один раз в каждом списке и отдаёт наиболее высоко ранжированный фрагмент из него. Переранжирование отдельно сортирует кандидатов по сумме обратных позиций BM25 и E5, чтобы сильнее учитывать верх списка. На `dev` исходный и секционный RRF дали 16/16 и MRR@5 0,8906, а секционный убрал повторы в семи запросах. Переранжирование дало MRR@5 0,8802, поэтому оставлено в интерфейсе как вариант для сравнения.

## Разбор ошибки CronJob

Вопрос «Новый запуск по расписанию должен заменить предыдущий, если тот ещё работает. Что настроить?» относится к разделу `cronjobs:114`, где описан `.spec.concurrencyPolicy: Replace`. Это диагностический пример из первой версии, вынесенный из нового теста. Его можно открыть кнопкой **CronJob** в режиме **Сравнить поиск**.

| Вариант | Позиция эталона |
| --- | ---: |
| BM25 | 1 |
| E5 + Qdrant | вне топ‑10 |
| RRF по фрагментам | 8 |
| RRF по разделам | 6 |
| Переранжирование | 1 |

В исходном RRF три места из первых пяти занимал один соседний раздел о создании заданий. Объединение по разделам освобождает эти места. Более резкий вес верхних позиций возвращает эталон первым на этом вопросе, хотя средний результат у такого варианта хуже на обеих новых выборках.

## Сигнал о недостатке источников

Для каждого запроса считаем максимальное покрытие термов одним из пяти фрагментов. Частые термы весят меньше. Термы, отсутствующие в корпусе, остаются в знаменателе. При покрытии ниже **0,25** интерфейс предупреждает, что подтверждений недостаточно. Порог выбран на `dev` по сумме долей правильно принятых и отклонённых запросов.

- На `dev` предупреждение появилось для 8 из 8 вопросов вне корпуса и для 1 из 16 вопросов с ответом.
- На `test` оно появилось для 6 из 8 вопросов вне корпуса и для 1 из 16 вопросов с ответом.
- Пример ложного предупреждения — вопрос о всплесках CPU. Примеры пропущенных предупреждений — пауза rollout Deployment и настройка FlowSchema. Общие технические слова дали высокое покрытие, хотя нужных инструкций в корпусе нет.

Сигнал оценивает совпадение слов и служит подсказкой для чтения. Подтверждённость фактов проверяется по источнику. Здесь измерялся поиск и сигнал о покрытии, а генерация через Yandex в эксперимент не входила.

## Воспроизведение

Запусти приложение через Compose с BM25, Qdrant и гибридным режимом. Затем из корня репозитория:

```bash
python -m scripts.evaluate_triage --split dev --output triage-dev.json
python -m scripts.evaluate_triage --split test --selected section_rrf --threshold 0.25 --output triage-test.json
```

Детальные результаты прогонов доступны в [dev](../evaluation/reports/triage-dev.json) и [test](../evaluation/reports/triage-test.json). [Первоначальные эксперименты](initial-experiments.md).
